다음 검색 미들웨어 — Jenkins + Ansible 기반 CI/CD 파이프라인 구축

2026.01 ~ 현재 · 주식회사 디케이테크인

배경

다음 포털 검색 미들웨어 서비스는 다수의 운영 서버에 배포되는 구조였지만, 기존에는 수동으로 빌드하고 각 서버에 직접 접속하여 배포하는 방식이었습니다. 서버 수가 늘어나면서 배포 시간이 길어지고, 서버별 배포 상태가 불일치하는 문제가 발생했으며, 배포 중 장애가 발생했을 때 롤백 절차도 수동으로 진행해야 하는 운영 리스크가 있었습니다.

문제 정의

  • 다수 서버에 대한 수동 배포로 인해 배포 시간이 길고 휴먼 에러 발생 가능성이 높음
  • 환경별(dev/stage/prod) 빌드·배포 프로세스가 통일되지 않아 환경 간 불일치 발생
  • 배포 실패 시 롤백 절차가 수동이라 장애 복구 시간이 길어지는 구조
  • 배포 중 서비스 중단 없이 트래픽을 처리해야 하는 무중단 배포 요구사항

해결 과정

1. Jenkins 파이프라인 설계 — 환경별 분기 전략

Jenkinsfile 기반 선언적 파이프라인을 구성하여 빌드부터 배포까지 자동화했습니다. 환경 파라미터(dev/stage/prod)에 따라 브랜치를 자동 선택하고, Maven 빌드 및 테스트를 거친 후 배포 아티팩트를 생성하는 구조입니다. 운영 환경 배포 시에는 수동 승인(Approval) 단계를 추가하여 의도하지 않은 배포를 방지했습니다.

Jenkins 파이프라인 흐름

Git Checkout → Maven Build & Test → Approval (prod) → Ansible Deploy

2. Ansible 기반 무중단 롤링 배포

Ansible Playbook을 활용하여 서버 한 대씩 순차적으로 배포하는 롤링 배포 전략을 적용했습니다. 배포 대상 서버를 로드밸런서에서 제거(Health Check DOWN)한 뒤 기존 트래픽이 완전히 빠질 때까지 대기하고, 새 버전을 배포한 후 다시 로드밸런서에 등록(Health Check UP)하는 방식으로 서비스 중단 없이 배포를 수행합니다.

롤링 배포 흐름 (서버 1대 기준)

Health Check DOWN → 트래픽 드레인 → 아티팩트 배포 → 서비스 재시작 → Smoke Test → Health Check UP

3. 자동 롤백 및 안정성 확보

릴리스 디렉토리를 타임스탬프 기반으로 관리하고 심볼릭 링크로 현재 버전을 가리키는 구조를 적용하여, 배포 실패 시 이전 릴리스로 심볼릭 링크를 즉시 복원하는 자동 롤백을 구현했습니다. 새 버전 배포 후에는 Smoke Test를 통해 핵심 API의 정상 응답을 검증하고, 애플리케이션 Warmup 과정을 거쳐 커넥션 풀과 캐시가 초기화된 상태에서 트래픽을 받도록 했습니다. 이전 릴리스는 최근 5개까지 보관하여 필요 시 수동 롤백도 가능하도록 했습니다.

배포 실패 시 자동 롤백 흐름

배포 실패 감지 → 심볼릭 링크 복원 → 이전 버전 재시작 → Health Check UP

4. 환경별 구성 관리

Ansible Inventory를 환경별(dev/stage/prod)로 분리하여 서버 목록, 서비스 포트, 배포 경로 등을 환경에 맞게 관리했습니다. Jinja2 템플릿을 활용하여 애플리케이션 설정 파일과 서비스 제어 스크립트를 환경 변수 기반으로 자동 생성하는 구조를 적용하여, 환경 간 설정 불일치를 방지했습니다.

결과

  • 수동 배포에서 Jenkins 파이프라인 기반 자동화로 전환하여 배포 시간 단축 및 휴먼 에러 제거
  • 롤링 배포 전략으로 다수 서버에 대한 무중단 배포 달성
  • 자동 롤백 구조로 배포 실패 시 빠른 장애 복구 가능
  • Smoke Test + Warmup 과정을 통해 배포 직후 서비스 안정성 확보
  • 환경별 Inventory 및 템플릿 분리로 dev/stage/prod 간 설정 일관성 유지

회고

CI/CD 파이프라인을 직접 구축하면서, 단순히 빌드·배포를 자동화하는 것이 아니라 "배포가 실패했을 때 어떻게 복구할 것인가"까지 설계하는 것이 중요하다는 것을 배웠습니다. 특히 롤링 배포에서 Health Check와 트래픽 드레인을 통해 사용자에게 영향을 주지 않으면서 배포하는 과정을 설계하고, Smoke Test로 배포 결과를 즉시 검증하는 구조를 만드는 것이 운영 환경의 안정성에 큰 차이를 만든다는 것을 체감했습니다.
